Opcional 1 – Simulación de Bloqueos y Conexiones Alternativas

1.1 Problema que se resuelve

En una red social modelada como un grafo no dirigido (nodos = usuarios, aristas = conexiones), un administrador puede bloquear una conexión específica entre dos usuarios. El objetivo es responder dos preguntas de forma automática:

  1. Después del bloqueo, ¿la red sigue siendo completamente conexa (es decir, todo par de usuarios sigue pudiendo comunicarse)?
  2. Si la red quedó desconectada, ¿cuál es el conjunto mínimo de nuevas conexiones que hay que agregar para restablecerla?

El caso de interés ocurre cuando la conexión bloqueada era un puente del grafo; es decir, la única arista que mantenía unidas dos partes de la red.

1.2 Estrategia de resolución

El algoritmo se desarrolla en cuatro pasos:

  1. Construcción del grafo sin la conexión bloqueada. Se genera un mapa de adyacencias no dirigido a partir del grafo original, omitiendo la arista bloqueada.
  2. BFS para identificar componentes. Se ejecuta una BFS desde cualquier nodo. Si todos los nodos quedan alcanzados, la red sigue conexa y el algoritmo termina. Si no, los nodos alcanzados forman la componente A y el resto forman la componente B.
  3. Generación de conexiones candidatas. Se generan únicamente pares (u, v) donde u ∈ A y v ∈ B. Cualquiera de esos pares, por construcción, reconecta las dos componentes.
  4. Backtracking sobre las candidatas. Se busca el subconjunto mínimo de candidatas que, al agregarse al grafo post-bloqueo, restaura la conectividad. La búsqueda itera desde tamaño 1 en adelante. Dado que una sola arista bloqueada crea a lo sumo dos componentes, el backtracking siempre termina en la primera candidata de tamaño 1.

1.3 Complejidad del algoritmo

Versión Generación de candidatas Backtracking Complejidad total
Original O(V²) pares (todos los pares no conectados) O(C(C,k) · (V+E)) con C = O(V²) O(V2k · (V+E))
Mejorada O(|A|·|B|) pares inter-componente ≤ O(V²/4) O(1) evaluaciones (siempre k=1, primera candidata) O(V + E)

El espacio adicional es O(V + E) para el mapa de adyacencias y los conjuntos de nodos visitados.

Propiedad clave: eliminar una arista de un grafo conexo produce a lo sumo dos componentes. Por lo tanto, la solución mínima tiene siempre exactamente una conexión nueva, y el backtracking nunca supera el tamaño 1.

1.4 Implementación de la mejora

La mejora central consiste en reemplazar la función estaConectado() (que devolvía un simple booleano luego de hacer BFS) por un nuevo método encontrarComponente(), que devuelve directamente el conjunto de nodos alcanzables desde el nodo inicial.

Esto permite que en simularBloqueo() se obtengan ambas componentes en un único recorrido BFS: la componente A proviene del resultado de la BFS, y la componente B se obtiene por complemento (todos los nodos menos A) en O(V), sin necesidad de un segundo recorrido.

La lista de candidatas deja de incluir todos los pares del grafo y pasa a incluir únicamente pares (u ∈ A, v ∈ B), lo que garantiza que cualquier candidata elegida reconecta la red. Con este invariante, la primera evaluación del backtracking siempre tiene éxito.

// ── Paso 1: BFS que devuelve la componente alcanzable (no sólo un booleano) ──
private Set<Usuario> encontrarComponente(Map<Usuario, Set<Usuario>> adj,
                                          Usuario inicio) {
    Set<Usuario> visitados = new HashSet<>();
    Queue<Usuario> cola = new LinkedList<>();
    cola.add(inicio);
    visitados.add(inicio);
    while (!cola.isEmpty()) {
        for (Usuario vecino : adj.get(cola.poll())) {
            if (visitados.add(vecino)) cola.add(vecino);
        }
    }
    return visitados;   // componente A
}

// ── Paso 2: lógica principal, con poda por componentes ──
public ResultadoBloqueo simularBloqueo(Grafo grafo, Conexion conexionBloqueada) {
    Map<Usuario, Set<Usuario>> adj = construirAdjSinConexion(grafo, conexionBloqueada);

    Set<Usuario> todos = grafo.getUsuarios();
    Set<Usuario> componenteA = encontrarComponente(adj, todos.iterator().next());

    if (componenteA.size() == todos.size()) {
        return new ResultadoBloqueo(conexionBloqueada, true, Collections.emptyList());
    }

    // ComponenteB = complemento de A (no se necesita un segundo BFS)
    Set<Usuario> componenteB = new HashSet<>(todos);
    componenteB.removeAll(componenteA);

    List<Conexion> candidatas = generarCandidatas(componenteA, componenteB);
    List<Conexion> minimas = buscarConexionesMinimas(adj, todos, candidatas);
    return new ResultadoBloqueo(conexionBloqueada, false, minimas);
}

// ── Paso 3: candidatas solo entre las dos componentes ──
private List<Conexion> generarCandidatas(Set<Usuario> componenteA,
                                           Set<Usuario> componenteB) {
    List<Conexion> candidatas = new ArrayList<>();
    for (Usuario u : componenteA) {
        for (Usuario v : componenteB) {
            candidatas.add(new Conexion(u, v, 1));
        }
    }
    return candidatas;   // cualquier elemento reconecta la red
}

Opcional 3 – Asignación Óptima de Administradores a Grupos

3.1 Problema que se resuelve

La red social cuenta con n grupos de usuarios y n administradores. Cada administrador tiene un valor de eficiencia (0–100) diferente para cada grupo. Se define ineficiencia = 100 − eficiencia.

El objetivo es encontrar una asignación biyectiva (un administrador por grupo, sin repetir) que minimice la suma total de ineficiencias. Este es el clásico problema de asignación (assignment problem).

Restricción: para valores de n moderados (≤ 20) la cantidad de permutaciones posibles es n!, lo que hace inviable una búsqueda exhaustiva directa.

3.2 Estrategia de resolución

Se utiliza Programación Dinámica con máscara de bits (bitmask DP), una técnica clásica para resolver el problema de asignación en O(n² · 2n).

La idea central es representar el estado del problema mediante un entero de n bits:

  • Si el bit i de la máscara está activo, significa que el administrador i ya fue asignado.
  • La cantidad de bits activos en la máscara indica cuántos grupos ya fueron cubiertos, y por lo tanto cuál es el siguiente grupo a asignar (los grupos se procesan en orden fijo 0, 1, …, n−1).

La tabla DP se define como:

dp[máscara] = ineficiencia mínima acumulada cuando exactamente los administradores indicados en máscara ya han sido asignados.

La transición es:

dp[máscara | (1 ≪ i)] = min(dp[máscara | (1 ≪ i)],   dp[máscara] + ineficiencia(admini, grupok))

donde k = popcount(máscara) es el índice del próximo grupo.

Una vez llenada la tabla, la asignación se reconstruye recorriendo las máscaras hacia atrás desde el estado final (todos los bits activos).

3.3 Justificación de la subestructura óptima

La DP es correcta porque el problema cumple el principio de subproblemas óptimos: la asignación óptima de los primeros k grupos se construye sobre la asignación óptima de los primeros k−1 grupos. Dado que los grupos se procesan en orden, no hay interferencia entre subproblemas.

3.4 Complejidad del algoritmo

Versión Tiempo Espacio Observaciones
Backtracking ingenuo (descartada) O(n!) O(n) Inviable para n > 12
Bitmask DP (implementada) O(n² · 2n) O(2n) Viable hasta n ≈ 20

Para n = 10: el backtracking evaluaría 3.628.800 permutaciones; la DP evalúa 10 · 1.024 = 10.240 transiciones — una reducción de ×354.

3.5 Implementación de la mejora

La versión original del problema se planteó con backtracking puro: se generaban todas las permutaciones posibles de administradores y se elegía la de menor costo, con complejidad O(n!).

La mejora consiste en reemplazar esa búsqueda exhaustiva por la tabla DP sobre máscaras de bits. Cada estado dp[mask] se calcula una sola vez y se reutiliza en todas las transiciones que parten de él, eliminando el solapamiento de cálculos que hace ineficiente el backtracking.

Se agrega también un arreglo auxiliar adminAsignado[] que registra, para cada estado, cuál fue el administrador elegido en la transición óptima. Esto permite reconstruir la solución completa en O(n) al final, sin necesidad de repetir ningún cálculo.

public ResultadoAsignacion calcularAsignacionOptima(List<Grupo> grupos,
                                                     List<Administrador> administradores) {
    int n = grupos.size();
    int totalMascaras = 1 << n;   // 2^n estados posibles

    // dp[mask] = ineficiencia mínima cuando los admins en 'mask' ya están asignados
    int[] dp = new int[totalMascaras];
    Arrays.fill(dp, Integer.MAX_VALUE);
    dp[0] = 0;

    // adminAsignado[mask] = admin elegido para llegar al estado 'mask'
    int[] adminAsignado = new int[totalMascaras];

    for (int mascara = 0; mascara < totalMascaras; mascara++) {
        if (dp[mascara] == Integer.MAX_VALUE) continue;

        // Siguiente grupo = cantidad de bits activos (admins ya asignados)
        int grupoActual = Integer.bitCount(mascara);
        if (grupoActual == n) continue;

        for (int admin = 0; admin < n; admin++) {
            if ((mascara & (1 << admin)) != 0) continue; // ya asignado

            int ineficiencia = 100 - administradores.get(admin).getEficiencia(grupoActual);
            int nuevaMascara = mascara | (1 << admin);
            int nuevoCosto   = dp[mascara] + ineficiencia;

            if (nuevoCosto < dp[nuevaMascara]) {
                dp[nuevaMascara]         = nuevoCosto;
                adminAsignado[nuevaMascara] = admin;   // guardar para reconstrucción
            }
        }
    }

    // Reconstrucción O(n): recorrer máscaras hacia atrás
    int[] asignacion = new int[n];
    int mascara = totalMascaras - 1;
    for (int grupo = n - 1; grupo >= 0; grupo--) {
        int admin = adminAsignado[mascara];
        asignacion[grupo] = admin;
        mascara ^= (1 << admin);   // desactivar el bit del admin elegido
    }

    return new ResultadoAsignacion(grupos, administradores, asignacion,
                                   dp[totalMascaras - 1]);
}
